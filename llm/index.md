# nemlake: index for agents

AEMO market data into a local Parquet lake. Rust only. Layers, dependencies pointing down: `crates/nemlake-cli` → `crates/nemlake-pipeline` → {`crates/nemlake-fetch`, `crates/nemlake-mms`, `crates/nemlake-store`} → `crates/nemlake-schema` → `crates/nemlake-schema-model` → `crates/nemlake-core`. Async at the edges (fetch, manifest, pipeline), sync in the core (scan, cast, Parquet); data crosses once per file as Arrow `RecordBatch`.
Each entry names where a thing starts. Read those files before you edit.

## Rules a hook or CI enforces

- Run tools through `just`, never with hand-picked flags. `just check` runs every hook, as CI does.
- `unsafe` is forbidden in every crate, so there is no mmap: zips are read through `BufReader<File>` (`crates/nemlake-mms/src/archive.rs`).
- The hot path is `crates/nemlake-mms/src/scan.rs`, `crates/nemlake-mms/src/fields.rs`, `crates/nemlake-mms/src/arrow_sink.rs`, `crates/nemlake-core/src/nemtime.rs`, `crates/nemlake-core/src/num.rs`: no allocation per row, no `chrono`/`jiff`/`regex` there, nothing `dyn` or `async` in the loop. Measure with `just bench-fast` before and after.
- A coverage floor in `coverage.json` only goes up; a budget in `bench/budgets.json` only tightens. Loosening one needs a `coverage-floor:` or `bench-budget:` line in the commit message (`just budget-check`).
- Every failure mode is a `Diagnostic` (`crates/nemlake-core/src/diag.rs`) with a stable `category.snake_name` code, a full-sentence message, and whatever context the layer knows (request, URL, file, entry, table, version, line, sample). Codes are never renamed; `docs/errors.md` is generated from them (`just errors-doc`).
- Table shapes come only from the registry (`crates/nemlake-schema`); nothing else hardcodes a column list. Schema files under `schemas/` are generated by `just schema-regen` from `testdata/`; hand edits go in fields marked `curated = true`; `just schema-check` fails on a diff.
- Parquet is written only through `LakeWriter` (`crates/nemlake-store/src/writer.rs`); a file exists only after rename, and the manifest row for it is written in the same step.
- The manifest schema changes only by a new numbered file in `crates/nemlake-store/src/manifest/migrations/`, never by editing an old one.
- Every HTTP request goes through `Fetcher` (`crates/nemlake-fetch/src/fetcher.rs`): one user agent, pacing, retries, cache, `--offline`.
- Fixtures under `testdata/` are AEMO public excerpts of at most 20 data rows each; attribution in `testdata/LICENCE.md`. Never commit a whole archive file.
- Network tests run only with `NEMLAKE_NET_TESTS=1` (`just net-test`). Unit tests never write under the real home directory; they use a temp home.
- Commits follow Conventional Commits (`feat:`, `fix:`, `chore:` …) with an imperative subject and no tool attribution.

## Features

- **Vocabulary**: months, archive file names in both AEMO schemes (`crates/nemlake-core/src/archive_name.rs`), MMS timestamps and numbers, I-row normalisation and fingerprints, the home layout, the config file, diagnostics and their aggregation. `crates/nemlake-core/src/`.
- **Schema model**: one TOML per table (`schemas/nem/mms/`), columns once, versions as column lists, `[[version.variant]]` for other shapes published under the same version; validation, widening rules, breaking-change detection, postcard blob. `crates/nemlake-schema-model/src/validate.rs`, `crates/nemlake-schema-model/src/compat.rs`, `crates/nemlake-schema-model/src/file.rs`.
- **Registry**: `crates/nemlake-schema/build.rs` validates `schemas/` at compile time; resolution of an I row is exact (the version or a declared variant), aliased or drift, strict or permissive. `crates/nemlake-schema/src/resolve.rs`, `crates/nemlake-schema/src/registry.rs`, `crates/nemlake-schema/src/arrow.rs`, `crates/nemlake-schema/src/infer.rs` (drafting a table, and extending one with a new version or variant), `crates/nemlake-schema/src/rules.rs` (the hash of the rules a shape is read by; raise `RULES_FORMAT` when the code itself converts differently). A user's own tables, in the schemas directory of the nemlake home, overlay the embedded ones (`Registry::with_overlay`, loaded in `crates/nemlake-cli/src/context.rs`).
- **Bootstrap**: CTL parser, data-model JSON reader, I-row sampler, merge with precedence and notes; `heads`/`ctls` fetch fixtures from nemweb through Range GETs (`crates/nemlake-schema-bootstrap/src/remote.rs`). `crates/nemlake-schema-bootstrap/src/`, `crates/nemlake-schema-bootstrap/snapshot_tables.toml`, fixtures in `testdata/bootstrap/MMSDM_2024_01/`.
- **MMS format**: scanner, field splitter, typed Arrow sink with two-pass rows and quarantine, zip walker (nested zips), inspect sink. `crates/nemlake-mms/src/`.
- **Fetch**: MMSDM archive listing and table matching for both month layouts, directory (2015+) and whole-month zip (2009-2014) (`crates/nemlake-fetch/src/mmsdm.rs`); one member of a remote zip read with ranged requests (`crates/nemlake-fetch/src/remotezip.rs`, `Fetcher::list_zip_members`); every request paced, and a refusal (403/429) trips a breaker for the rest of the run (`crates/nemlake-fetch/src/fetcher.rs`), IIS listing parser, WEM manifests, transport trait with offline and canned test transports; downloads kept untransformed in an archive that mirrors each URL, with a request record beside each file, and a separate throwaway cache of listings (`crates/nemlake-fetch/src/cache.rs`).
- **Store**: Hive Parquet writer with atomic rename (`crates/nemlake-store/src/parquet_hive.rs`), month partitioner, SQLite manifest and its async actor (`crates/nemlake-store/src/manifest/`).
- **Pipeline**: list → fetch → ingest on blocking workers → commit; every file attempted; exit codes. Each ingest records its transform (source shape, rules hash, schema source) in the Parquet footer and the manifest; a source whose rules changed is read again (`rules_current`), and `Input::Stale` lists every such source from the manifest. `crates/nemlake-pipeline/src/run.rs`, `crates/nemlake-pipeline/src/ingest_file.rs`, `crates/nemlake-pipeline/src/report.rs`.
- **Command**: `fetch nem`, `ingest`, `reingest`, `inspect`, `ls`, `errors`, `verify`, `schema`, `archive`, `cache`, `wem`. `crates/nemlake-cli/src/cli.rs`, `crates/nemlake-cli/src/commands/`.
- **Gates**: coverage (`just cover`), benchmarks (`just bench`, `just bench-fast`), ratchet (`just budget-check`), agent index (`just llm-check`), error catalogue (`just errors-check`). `crates/xtask/src/`, `crates/nemlake-bench/src/main.rs`, `bench/budgets.json`, `coverage.json`.
