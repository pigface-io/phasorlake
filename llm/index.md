# nemlake: index for agents

AEMO market data into a local Parquet lake. Rust only. Layers, dependencies pointing down: `crates/nemlake-cli` → `crates/nemlake-pipeline` → {`crates/nemlake-acquire`, `crates/nemlake-conform`, `crates/nemlake-writer`}; `crates/nemlake-conform` → {`crates/nemlake-decode`, `crates/nemlake-registry`} → `crates/nemlake-core`. Decode never depends on the registry (the compiler holds it); `crates/nemlake-census` is tooling beside them. Async at the edges (fetch, manifest, pipeline), sync in the core (scan, cast, Parquet); data crosses once per file as Arrow `RecordBatch`.
Each entry names where a thing starts. Read those files before you edit.

## Rules a hook or CI enforces

- Run tools through `just`, never with hand-picked flags. `just check` runs every hook, as CI does.
- `unsafe` is forbidden in every crate, so there is no mmap: zips are read through `BufReader<File>` (`crates/nemlake-decode/src/archive.rs`).
- The hot path is `crates/nemlake-decode/src/scan.rs`, `crates/nemlake-decode/src/fields.rs`, `crates/nemlake-conform/src/arrow_sink.rs`, `crates/nemlake-conform/src/builders.rs`, `crates/nemlake-core/src/nemtime.rs`, `crates/nemlake-core/src/num.rs`: no allocation per row, no `chrono`/`jiff`/`regex` there, nothing `dyn` or `async` in the loop. Measure with `just bench-fast` before and after.
- A coverage floor in `coverage.json` only goes up; a budget in `bench/budgets.json` only tightens. Loosening one needs a `coverage-floor:` or `bench-budget:` line in the commit message (`just budget-check`).
- Every failure mode is a `Diagnostic` (`crates/nemlake-core/src/diag.rs`) with a stable `category.snake_name` code, a full-sentence message, and whatever context the layer knows (request, URL, file, entry, table, version, line, sample). Codes are never renamed; `docs/errors.md` is generated from them (`just errors-doc`).
- Table shapes come only from the registry (`crates/nemlake-registry`); nothing else hardcodes a column list. Schema files under `schemas/` are generated by `just schema-regen` from `testdata/`; hand edits go in fields marked `curated = true`; `just schema-check` fails on a diff.
- Parquet is written only through `LakeWriter` (`crates/nemlake-writer/src/writer.rs`); a file exists only after rename, and the manifest row for it is written in the same step.
- The manifest schema changes only by a new numbered file in `crates/nemlake-writer/src/manifest/migrations/`, never by editing an old one.
- Every HTTP request goes through `Fetcher` (`crates/nemlake-acquire/src/fetcher.rs`): one user agent, pacing, retries, cache, `--offline`.
- Fixtures under `testdata/` are AEMO public excerpts of at most 20 data rows each; attribution in `testdata/LICENCE.md`. Never commit a whole archive file.
- Network tests run only with `NEMLAKE_NET_TESTS=1` (`just net-test`). Unit tests never write under the real home directory; they use a temp home.
- Commits follow Conventional Commits (`feat:`, `fix:`, `chore:` …) with an imperative subject and no tool attribution.

## Features

- **Vocabulary**: months, archive file names in both AEMO schemes (`crates/nemlake-core/src/archive_name.rs`), MMS timestamps and numbers, I-row normalisation and fingerprints, the home layout, the config file, diagnostics and their aggregation. `crates/nemlake-core/src/`.
- **Schema model** (`crates/nemlake-registry/src/file_model/`): one TOML per table (`schemas/nem/mms/`), columns once, versions as column lists, `[[version.variant]]` for other shapes published under the same version, `[[rule]]` for hand-written routes of file columns to lake columns within a span of months, a version or a column list (`RuleDef`; applied in `Registry::resolve_in`, never generated); validation, widening rules, breaking-change detection, postcard blob, the parser of AEMO's SQL*Loader control files (`crates/nemlake-registry/src/file_model/ctl.rs`). `crates/nemlake-registry/src/file_model/validate.rs`, `crates/nemlake-registry/src/file_model/compat.rs`, `crates/nemlake-registry/src/file_model/file.rs`.
- **Registry**: `crates/nemlake-registry/build.rs` validates `schemas/` at compile time; resolution of an I row is exact (the version or a declared variant), aliased or drift, strict or permissive, and ends in a `ConformancePlan` (`crates/nemlake-registry/src/plan.rs`): a serialisable value of routes, casts, key and time column that conform applies; `nemlake schema plan` prints one. `crates/nemlake-registry/src/resolve.rs`, `crates/nemlake-registry/src/registry.rs`, `crates/nemlake-registry/src/arrow.rs`, `crates/nemlake-registry/src/infer.rs` (drafting a table, and extending one with a new version or variant), `crates/nemlake-registry/src/rules.rs` (the hash of the rules a shape is read by; raise `RULES_FORMAT` when the code itself converts differently). A user's own tables, in the schemas directory of the nemlake home, overlay the embedded ones (`Registry::with_overlay`, loaded in `crates/nemlake-cli/src/context.rs`).
- **Census** (schema bootstrap): data-model JSON reader, I-row sampler, merge with precedence and notes (no alias is inferred: two names are two columns unless a curated alias says otherwise); `heads`/`ctls` fetch fixtures from nemweb through Range GETs (`crates/nemlake-census/src/remote.rs`), `datamodel` reads AEMO's data-model report into the JSON (`crates/nemlake-census/src/dmreport.rs`). Every bootstrap input is produced by a recipe (`just schema-fixtures`, `just schema-datamodel`); none is made by hand. `crates/nemlake-census/src/`, `crates/nemlake-census/snapshot_tables.toml`, fixtures in `testdata/bootstrap/`. Which tables are standing data (snapshots) is AEMO's README list plus tables the samples prove (`crates/nemlake-census/src/standing.rs`), never a judgment.
- **Decode** (MMS format): scanner, field splitter, zip walker (nested zips), quarantine file writer; hands each block's I row and its untyped rows to a `Sink`. `crates/nemlake-decode/src/`.
- **Conform**: the typed Arrow sink, resolving each block through the registry, two-pass rows (parse all, then append), quarantine decisions, timestamp clamping; the inspect sink. `crates/nemlake-conform/src/`.
- **Acquire**: MMSDM archive listing and table matching for both month layouts, directory (2015+) and whole-month zip (2009-2014) (`crates/nemlake-acquire/src/mmsdm.rs`); one member of a remote zip read with ranged requests (`crates/nemlake-acquire/src/remotezip.rs`, `Fetcher::list_zip_members`); every request paced, and a refusal (403/429) trips a breaker for the rest of the run (`crates/nemlake-acquire/src/fetcher.rs`), IIS listing parser, WEM manifests, transport trait with offline and canned test transports; downloads kept untransformed in an archive that mirrors each URL, with a request record beside each file, and a separate throwaway cache of listings (`crates/nemlake-acquire/src/cache.rs`).
- **Writer**: Hive Parquet writer with atomic rename (`crates/nemlake-writer/src/parquet_hive.rs`), month partitioner, SQLite manifest and its async actor (`crates/nemlake-writer/src/manifest/`).
- **Pipeline**: list → fetch → ingest on blocking workers → commit; every file attempted; exit codes. Each ingest records its transform (source shape, rules hash, schema source) in the Parquet footer and the manifest; a source whose rules changed is read again (`rules_current`), and `Input::Stale` lists every such source from the manifest. `crates/nemlake-pipeline/src/run.rs`, `crates/nemlake-pipeline/src/ingest_file.rs`, `crates/nemlake-pipeline/src/report.rs`.
- **Command**: `fetch nem`, `ingest`, `reingest`, `inspect`, `ls`, `errors`, `verify`, `schema`, `archive`, `cache`, `wem`. `crates/nemlake-cli/src/cli.rs`, `crates/nemlake-cli/src/commands/`.
- **Gates**: coverage (`just cover`), benchmarks (`just bench`, `just bench-fast`), ratchet (`just budget-check`), agent index (`just llm-check`), error catalogue (`just errors-check`). `crates/xtask/src/`, `crates/nemlake-bench/src/main.rs`, `bench/budgets.json`, `coverage.json`.
