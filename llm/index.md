# nemlake: index for agents

AEMO market data into a local Parquet lake. Rust only. Layers, dependencies pointing down: `crates/nemlake-cli` → `crates/nemlake-pipeline` → {`crates/nemlake-acquire`, `crates/nemlake-conform`, `crates/nemlake-writer`}; `crates/nemlake-conform` → {`crates/nemlake-decode`, `crates/nemlake-registry`} → `crates/nemlake-core`. Decode never depends on the registry (the compiler holds it); `crates/nemlake-census` is tooling beside them. Async at the edges (fetch, manifest, pipeline), sync in the core (scan, cast, Parquet); data crosses once per file as Arrow `RecordBatch`.
Each entry names where a thing starts. Read those files before you edit.

## Rules a hook or CI enforces

- Run tools through `just`, never with hand-picked flags. `just check` runs every hook, as CI does.
- `unsafe` is forbidden in every crate, so there is no mmap: zips are read through `BufReader<File>` (`crates/nemlake-decode/src/archive.rs`).
- The hot path is `crates/nemlake-decode/src/scan.rs`, `crates/nemlake-decode/src/fields.rs`, `crates/nemlake-conform/src/arrow_sink.rs`, `crates/nemlake-conform/src/builders.rs`, `crates/nemlake-core/src/nemtime.rs`, `crates/nemlake-core/src/num.rs`: no allocation per row, no `chrono`/`jiff`/`regex` there, nothing `dyn` or `async` in the loop. Measure with `just bench-fast` before and after.
- A coverage floor in `coverage.json` only goes up; a budget in `bench/budgets.json` only tightens. Loosening one needs a `coverage-floor:` or `bench-budget:` line in the commit message (`just budget-check`).
- Every failure mode is a `Diagnostic` (`crates/nemlake-core/src/diag.rs`) with a stable `category.snake_name` code, a full-sentence message, and whatever context the layer knows (request, URL, file, entry, table, version, line, sample). Codes are never renamed; `docs/errors.md` is generated from them (`just errors-doc`).
- Table shapes come only from the registry (`crates/nemlake-registry`); nothing else hardcodes a column list. Each table is a directory such as `schemas/nem/DISPATCH_UNIT_SCADA/`: a hand-editable table file that is ours, and AEMO's control files kept byte for byte beside it (hash checked at build time). Tools only append increments and columns; an existing increment, column id or type is never rewritten by a tool.
- Parquet is written only through `LakeWriter` (`crates/nemlake-writer/src/writer.rs`); a file exists only after rename, and the manifest row for it is written in the same step.
- The manifest schema changes only by a new numbered file in `crates/nemlake-writer/src/manifest/migrations/`, never by editing an old one.
- Every HTTP request goes through `Fetcher` (`crates/nemlake-acquire/src/fetcher.rs`): one user agent, pacing, retries, the archive, `--offline`. A file is downloaded whole, once; no cache, no ranged reads.
- Fixtures under `testdata/` are AEMO public excerpts of at most 20 data rows each; attribution in `testdata/LICENCE.md`. Never commit a whole archive file.
- Network tests run only with `NEMLAKE_NET_TESTS=1` (`just net-test`). Unit tests never write under the real home directory; they use a temp home.
- Commits follow Conventional Commits (`feat:`, `fix:`, `chore:` …) with an imperative subject and no tool attribution.

## Features

- **Vocabulary**: months, archive file names in both AEMO schemes (`crates/nemlake-core/src/archive_name.rs`), MMS timestamps and numbers, I-row normalisation and fingerprints, the content-addressed shape id over names and control-file type classes (`crates/nemlake-core/src/shape.rs`; raise `SHAPE_FORMAT` when the canonical form changes), the home layout, the config file, diagnostics and their aggregation. `crates/nemlake-core/src/`.
- **Schema model** (`crates/nemlake-registry/src/file_model/`): our schema per table: columns with exact types (`string`, `double`, `long`, `boolean`, `date`, `timestamp_ns`) and stable ids (Parquet field ids), which persist; and increments `TABLE@n`, each the file shape one AEMO control file sets from a month on, with its CTL and the I-row versions seen (`crates/nemlake-registry/src/file_model/model.rs`). A renamed column is a new column. Validation, breaking changes (only Iceberg promotions; none of ours), postcard blob, the parser of AEMO's SQL*Loader control files (`crates/nemlake-registry/src/file_model/ctl.rs`). Also its validate, compat and file modules.
- **Registry**: `crates/nemlake-registry/build.rs` validates `schemas/` at compile time; a block of month M resolves against the increment in force at M (no month: the increment with its columns, else the latest): `conforms`, `deviates` (strict mode refuses; a column the table lacks is kept as text) or `derived` (no table claims the pair; every column text). It ends in a `ConformancePlan` (`crates/nemlake-registry/src/plan.rs`): routes, casts, key and time column that conform applies; `nemlake schema plan` prints one. `crates/nemlake-registry/src/resolve.rs`, `crates/nemlake-registry/src/registry.rs`, `crates/nemlake-registry/src/arrow.rs`. `PlanHash` covers only what decides a shape's output, the increment included (raise `PLAN_FORMAT` when the code itself converts differently). A user's own tables, laid out like `schemas/` in the nemlake home, overlay the embedded ones (`Registry::with_overlay`, loaded in `crates/nemlake-cli/src/context.rs`).
- **Census**: `just census` reads each archived file of a month in full, offline (nested zips too, `ScanOptions::headers_only`), recording each block (shape id, rows) in `schemas/nem/census/` and `schemas/nem/shapes/` (`crates/nemlake-census/src/census.rs`); `nemlake fetch nem` downloads the month first. `just schema-sync` appends an increment where a month's CTL lays a table out anew, starts a missing table (`crates/nemlake-census/src/sync.rs`); `just schema-sync-check` fails on any change. `fixtures` cuts a month's CTLs, README and heads from the local archive (`crates/nemlake-census/src/fixtures.rs`), `datamodel` reads AEMO's data-model report into the JSON (`crates/nemlake-census/src/dmreport.rs`). Fixtures and data model come from recipes (`just schema-fixtures`, `just schema-datamodel`). `crates/nemlake-census/snapshot_tables.toml`, fixtures in `testdata/bootstrap/`. Which tables are standing data (snapshots) is AEMO's README list plus tables the samples prove (`crates/nemlake-census/src/standing.rs`), never a judgment.
- **Decode** (MMS format): scanner, field splitter, zip walker (nested zips), quarantine file writer; hands each block's I row and its untyped rows to a `Sink`. `crates/nemlake-decode/src/`.
- **Conform**: the typed Arrow sink, resolving each block through the registry, two-pass rows (parse all, then append), the value net (a value that does not fit is null with its text in `{col}__raw`; only a row of the wrong structure is quarantined), timestamp clamping; the inspect sink. `crates/nemlake-conform/src/`.
- **Acquire**: MMSDM listing for both month layouts, directory (2015+, with its CTLs and README) and whole-month zip (2009-2014, one file) (`crates/nemlake-acquire/src/mmsdm.rs`); paced requests, a refusal (403/429) trips a breaker, bodies streamed as `Bytes` to a blocking writer (`crates/nemlake-acquire/src/fetcher.rs`); IIS listing parser, WEM manifests, offline and canned transports; the archive mirrors each URL with a sidecar (`crates/nemlake-acquire/src/archive.rs`).
- **Writer**: Hive Parquet writer with atomic rename (`crates/nemlake-writer/src/parquet_hive.rs`), month partitioner, SQLite manifest and its async actor (`crates/nemlake-writer/src/manifest/`).
- **Pipeline**: list → fetch → ingest on blocking workers → commit (`RunOptions::ingest` false: download only; `Input::Archive` reads archived months); every file attempted; exit codes. A batch with columns its open file lacks (`{col}__raw`, a kept null) continues the partition in a further part file. Each ingest records its transform (source shape, plan hash, census shape id, schema source) in the Parquet footer and the manifest; a source whose plan changed is read again (`plans_current`), and `Input::Stale` lists every such source from the manifest. `crates/nemlake-pipeline/src/run.rs`, `crates/nemlake-pipeline/src/ingest_file.rs`, `crates/nemlake-pipeline/src/report.rs`.
- **Command**: `fetch nem` (download only), `ingest` (archived months or local files), `reingest`, `inspect`, `ls`, `errors`, `verify`, `schema`, `archive`, `wem`. `crates/nemlake-cli/src/cli.rs`, `crates/nemlake-cli/src/commands/`.
- **Gates**: coverage (`just cover`), benchmarks (`just bench`, `just bench-fast`), ratchet (`just budget-check`), agent index (`just llm-check`), error catalogue (`just errors-check`), census against the registry (`just census-check`, `crates/xtask/src/census_check.rs`). `crates/xtask/src/`, `crates/nemlake-bench/src/main.rs`, `bench/budgets.json`, `coverage.json`.
